# 面试回答框架

## STAR 法则

- Situation：项目背景是什么。
- Task：你要解决的核心问题是什么。
- Action：你采取了哪些设计、开发和优化动作。
- Result：结果如何，最好有量化指标。

## 讲项目时建议覆盖的点

- 系统主链路：用户输入如何流转到模型、工具和知识库。
- 你负责的模块：不要泛泛而谈，要明确文件、接口或功能边界。
- 工程问题：举 1 到 2 个你实际修过的 bug 或稳定性问题。
- 权衡与取舍：为什么先做 MVP，为什么没有一开始就引入更多复杂功能。

## 适合本项目的回答重点

- 如何把开源平台收敛成“求职面试助手”场景。
- 为什么新增 `resume_match` 这样的垂直工具。
- 如何利用知识库提升面试问答和简历优化的稳定性。
- 如何通过 Skill 或系统提示词约束输出风格，避免编造经历。

# 项目经历写作建议

## 基本原则

- 先写项目目标，再写你的职责，最后写结果。
- 不要只写“做了什么”，要写“为什么这样做”和“带来了什么效果”。
- 结果尽量量化，例如响应速度、准确率、可用性、开发效率、问题定位时间。

## 推荐结构

1. 项目背景：这个项目解决什么问题。
2. 技术方案：你使用了哪些技术和架构。
3. 个人职责：你具体负责哪些模块。
4. 结果与优化：上线效果、性能提升、工程修复、用户价值。

## 面向大模型应用岗位的表达重点

- 强调 Agent、RAG、Prompt、Tool Calling、SSE、知识库、部署等关键词。
- 如果是开源二次开发，要明确说明你负责的改动范围和实际贡献。
- 不要声称自己训练或微调了大模型，除非你真的做过。

# 求职面试助手项目包装说明

## 项目定位

这个项目更适合包装成：

`基于开源 AgentChat 的求职面试助手二次开发项目`

不要包装成：

`独立从零开发的 Agent 平台`

更稳妥的表达方式是强调你做了以下工作：

1. 完成开源项目的场景收敛与功能重构。
2. 新增面向求职场景的 Agent Tool 与默认 Agent。
3. 补充知识库内容，形成简历优化与面试准备闭环。
4. 修复若干后端接口与初始化流程中的工程问题。

## 简历写法示例

### 版本一：适合实习简历

**求职面试助手（基于 AgentChat 二次开发）**

- 基于开源 Agent 平台完成求职场景二次开发，新增 `resume_match` 工具，实现岗位 JD 与简历内容的结构化匹配分析。
- 设计“匹配度评分 / 优势提炼 / 缺口识别 / 简历修改建议 / 面试准备重点”输出链路，提升 Agent 在求职辅导场景下的可用性。
- 补充求职场景知识库文档，结合 Agent 工具调用与 RAG 检索，支持简历优化、项目改写与面试问答准备。
- 修复后端若干稳定性问题，包括工作台会话创建、权限校验、默认工具增量同步、异常处理与检索逻辑错误。

### 版本二：更偏大模型应用开发

**LLM 求职面试助手（AgentChat Secondary Development）**

- 在开源 AgentChat 项目上完成求职场景化改造，设计并接入自定义 Tool `resume_match`，调用大模型输出标准化 JSON 结果并格式化为可读分析报告。
- 新增系统默认 Agent“求职面试助手”，自动绑定工具与知识库素材，降低演示和初始化成本。
- 结合知识库文档构建岗位分析与面试辅导场景，形成 Tool Calling + Prompt Engineering + RAG 的应用闭环。
- 对项目中的会话创建、工具映射、权限校验、用量统计异常返回、ES 检索等问题进行修复，提升工程可运行性。

## 面试时怎么介绍

可以按下面这套顺序讲：

1. 先讲背景：原项目是通用 Agent 平台，功能很多但场景发散。
2. 再讲问题：如果直接放简历，和“大模型应用开发实习生”岗位的相关性不够强。
3. 再讲你的改造：我把它收敛成一个求职面试助手，重点做了 Tool、Agent、知识库和后端流程修复。
4. 最后讲结果：项目从“通用平台”变成了“可演示、可讲述、与岗位贴近”的 LLM 应用项目。

## 你要能说清楚的技术点

### 1. 自定义 Tool

- 新增 `resume_match` 工具。
- 输入是岗位 JD、简历内容、目标岗位名称。
- 输出是结构化分析结果，不只是自由问答。
- 通过 JSON 输出约束降低模型结果漂移，提高结果可读性。

### 2. Agent 场景化

- 新增默认 Agent“求职面试助手”。
- 启动时自动同步默认工具与默认 Agent。
- 已初始化系统也能增量补齐新工具，避免老数据环境缺少新增能力。

### 3. RAG 场景收敛

- 增加求职场景知识库素材。
- 让 Agent 不只会给泛化建议，而是能围绕简历表达、项目改写、面试回答结构给出更稳定的输出。

### 4. 工程修复

- 修复工作台会话创建接口缺失。
- 修复工作台会话权限校验缺失。
- 修复多个接口错误地 `return HTTPException` 的问题。
- 修复 ES 检索变量名错误。
- 修复工具映射名称不一致导致的调用问题。
- 修复部分模块 import 时强依赖配置的问题，改成懒加载，提升可启动性。

## 演示脚本

建议你本地演示时按这个顺序：

1. 打开“求职面试助手”。
2. 贴入一个“大模型应用开发实习生”岗位 JD。
3. 再贴入你的简历项目描述。
4. 展示 `resume_match` 输出的匹配度、缺口、修改建议。
5. 继续追问“把这段项目经历改成更适合实习简历的版本”。
6. 最后问“如果你是面试官，你会怎么追问这个项目”。

## 必须避免的表述

- 不要说这个平台是你从零开发的。
- 不要说底层 Agent 架构全部由你设计。
- 不要虚构线上用户量、生产流量或企业级部署。

## 建议的真实表述

- 我基于开源 AgentChat 做了面向求职场景的二次开发。
- 我主要负责场景设计、自定义工具开发、知识库整理，以及部分后端逻辑修复。
- 这个项目重点体现的是我做 LLM 应用集成与场景落地的能力，而不是从零造一个通用框架。

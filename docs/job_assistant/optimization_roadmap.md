# 求职面试助手下一阶段优化路线图

## 文档目的

这份文档不是功能清单，而是下一阶段的优化主线。

目标有两个：

1. 把当前项目从“基于几个 Prompt Tool 的场景化聊天”继续做深。
2. 让项目更像一个完整的大模型应用，而不是停留在“能跑 Demo”的阶段。

当前项目已经完成的部分主要是：

- 默认 Agent：`求职面试助手`
- 自定义 Tool：`resume_match`、`resume_rewrite`、`interview_followup`
- 前端接入：求职助手入口、快捷提示、执行轨迹、简历匹配卡片、简历改写卡片、面试追问卡片
- 基础工程修复：默认工具同步、会话异常处理、执行轨迹可观测性
- 输入链路升级：支持上传 PDF / DOCX / TXT / MD 后解析正文并注入对话上下文

截至 2026-04-21，下面两条优化主线已经完成了首版落地：

- P0：真实文件解析链路
- P2：结构化前端结果卡片

剩余更值得继续深挖的部分是：

- 文件解析状态展示
- 多步工作流编排
- 评测样例和调用统计

下一步不建议继续横向加很多新功能，而是建议沿着下面 4 条主线纵向做深。

## 优先级排序

### P0：真实文件解析链路

当前上传文件只是把 `file_url` 拼接到用户输入里，并没有真正读取简历内容。

这会直接影响项目的真实性，因为用户感知上是“支持上传简历”，但实际能力更像“支持上传链接”。

这一阶段的目标是：

- 支持读取 PDF / DOCX 简历内容
- 做基础文本清洗
- 把解析后的内容作为结构化输入传给 Agent / Tool

价值：

- 这是最容易被面试官问到的真实性问题
- 做完之后，项目才真正具备“上传简历 -> 自动分析”的完整链路

对应详细文档：

- `file_parsing_and_resume_ingestion.md`

### P1：多步工作流编排

当前主流程更接近：

`用户输入 -> Agent 判断调用哪个 Tool -> 返回结果`

下一步应该升级为更清晰的多步流程：

`识别任务 -> 解析输入材料 -> 调用匹配/改写/追问 Tool -> 汇总生成结果`

价值：

- 让项目真正体现 Agent Workflow / Orchestration
- 更适合在简历和面试里讲“多步任务拆解”和“工具协同”

对应详细文档：

- `agent_workflow_upgrade.md`

### P2：结构化前端与结果落地

目前只有 `resume_match` 做了结构化卡片，另外两个 Tool 还是纯文本。

下一步应该统一做成结构化展示，包括：

- 简历改写卡片
- 面试追问卡片
- 执行轨迹可视化增强
- 一键复制、一键继续追问

价值：

- 提升产品完成度
- 把 Tool 调用结果真正“落到前端体验里”

对应详细文档：

- `structured_output_and_evaluation.md`

### P3：评测与可观测性

当前已经补了执行轨迹，但还缺更正式的评测与统计。

下一步建议补：

- Tool 调用成功率、失败率、耗时
- 固定测试样例集
- 输出质量回归检查

价值：

- 让项目更像“工程化 LLM 应用”
- 面试时可以讲评测、监控、可维护性

对应详细文档：

- `structured_output_and_evaluation.md`

## 推荐执行顺序

建议按下面顺序推进，而不是并行乱做。

### 第一步

先做真实文件解析。

原因：

- 这是当前能力缺口里最明显的一项
- 它会直接影响后面的匹配、改写、追问质量

### 第二步

在文件解析完成后做多步工作流。

原因：

- 只有输入材料足够真实，工作流编排才有意义
- 否则只是把不稳定输入换成了更复杂的流程

### 第三步

补结构化前端和交互细节。

原因：

- 当前后端能力已经逐步成形
- 前端统一展示后，更容易演示，也更适合写进简历

### 第四步

最后补评测和可观测性。

原因：

- 在主要能力稳定后做评测，成本最低
- 更容易形成稳定的演示数据和项目总结

- 结构化输入构建

### 多步工作流

可以补足的技术关键词：

- Agent Workflow
- Tool Calling
- 多步任务拆解
- 状态流转
- LangGraph / 工作流编排

### 结构化前端

可以补足的技术关键词：

- SSE 流式事件
- 结构化结果渲染
- 前后端协议设计
- Agent 可观测性 UI

### 评测与监控

可以补足的技术关键词：

- LLM Application Evaluation
- Tool Calling Observability
- Prompt 回归测试
- 质量评估指标

## 简历视角下最值得做的 3 件事

如果时间有限，只做下面 3 件就够了：

1. 真实文件解析
2. 多步工作流编排
3. 结构化前端结果卡片

这 3 件做完，项目就会从：

`场景化 Prompt Demo`

更接近升级成：

`具备真实输入、Agent 编排、结构化展示的 LLM 应用`

## 当前结论

这个项目下一阶段不应该再优先堆新 Tool，而应该优先把：

- 输入链路
- Agent 编排
- 前端结果落地
- 评测体系

这 4 个部分补完整。

只有这样，项目才会更像一个成熟的“大模型应用开发”作品，而不是一个二次开发过的聊天页面。

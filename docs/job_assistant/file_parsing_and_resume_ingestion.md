# 求职面试助手优化专题一：真实文件解析与简历接入

## 为什么先做这个

当前上传文件的链路是：

`前端上传文件 -> 后端返回 file_url -> completion 接口把链接拼进用户输入`

这意味着：

- Agent 并没有真正读取文件内容
- Tool 也没有拿到结构化的简历文本
- 用户以为自己上传了简历，实际上模型只看到了一个链接

这会导致一个明显问题：

项目看起来支持“上传简历”，但实际上并没有做真实解析。

## 当前实现位置

重点入口：

- `src/frontend/src/pages/conversation/chatPage/chatPage.vue`
- `src/backend/agentchat/api/v1/upload.py`
- `src/backend/agentchat/api/v1/completion.py`
- `src/backend/agentchat/utils/helpers.py`

当前最关键的限制在：

- `build_completion_user_input(user_input, file_url)`

它只是简单返回：

- 用户输入
- 加上一段“上传的文件链接”

这不是真正的文件理解链路。

## 优化目标

把文件上传改造成完整的输入处理流程：

1. 用户上传 PDF / DOCX 简历
2. 后端读取文件内容
3. 解析出纯文本
4. 做基础清洗和截断
5. 把结果作为结构化简历文本传给 Tool

最终目标不是“支持上传”，而是：

`支持把上传的简历变成 Agent 可用的真实上下文`

## 推荐实现方案

### 方案一：轻量版本

适合先快速做通。

流程：

1. 用户上传文件
2. 后端根据文件类型选择解析器
3. 提取纯文本
4. 保存解析结果
5. completion 接口优先读取解析后的文本，而不是只传链接

可支持的类型：

- `.pdf`
- `.docx`
- 可选：`.md`、`.txt`

### 方案二：结构化版本

在轻量版本基础上继续做深。

除了纯文本外，再抽取下面几类字段：

- 基本信息
- 教育经历
- 技能栈
- 项目经历
- 实习经历
- 奖项/证书

这样后面的 Tool 可以直接拿结构化字段做分析，而不是全靠大模型自己拆。

## 技术设计建议

### 1. 增加文件解析服务层

建议新增一个服务模块，例如：

- `agentchat/services/resume_parser/`

内部可以拆成：

- `pdf_parser.py`
- `docx_parser.py`
- `cleaner.py`
- `schema.py`

### 2. completion 接口增加“解析结果读取”

不要再只传 `file_url`。

建议改成：

- 如果用户有上传文件
- 优先读取解析后的文件文本
- 再决定如何注入 prompt 或传给 tool

### 3. Tool 层支持“简历正文优先”

例如 `resume_match`、`resume_rewrite` 可以优先使用：

- 用户显式粘贴的内容
- 如果没有，再使用解析后的简历文本

这样用户体验会更稳定。

## 数据流建议

推荐的数据流：

1. `upload`
   - 返回文件 URL
   - 同时创建一条解析任务

2. `parse`
   - 根据文件类型抽取文本
   - 保存为“文件解析结果”

3. `completion`
   - 查询解析结果
   - 将解析文本注入用户上下文

4. `tool`
   - 直接拿到简历文本做分析

## 需要注意的问题

### 文件质量问题

PDF 可能有下面这些情况：

- 扫描版
- 双栏排版
- 中英文混排
- 项目符号丢失

所以解析结果不可能一步到位，需要至少做基础清洗。

### Token 长度问题

完整简历正文可能比较长。

建议做：

- 最大长度限制
- 分段截断
- 关键字段优先保留

### 错误处理

上传成功不代表解析成功。

建议增加状态：

- `uploaded`
- `parsing`
- `parsed`
- `parse_failed`

这样前端可以明确告诉用户：

- 文件已上传
- 文件已解析
- 当前解析失败，需要改为粘贴文本

## 这一步做完后，你能怎么讲

你可以把项目描述从：

`支持用户上传简历做匹配分析`

升级成：

`设计并实现简历文件接入链路，支持 PDF / DOCX 上传、文本抽取与清洗，将非结构化简历内容转化为 Agent 可消费的上下文输入。`

这个说法会更像真正做过 LLM 应用接入。

## 推荐落地顺序

1. 支持 PDF / DOCX 文本提取
2. 在 completion 中读取解析结果
3. 给前端补解析状态提示
4. 再考虑做结构化字段抽取

## 当前阶段最重要的原则

先把“用户上传的文件真的被用到了”做实。

不要一开始就追求把简历解析成特别复杂的结构化 JSON。

第一目标是：

`让上传功能从“假的”变成“真的”`
